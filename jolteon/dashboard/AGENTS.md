# Dashboard UI work

Read `UI_GUIDELINES.md` before creating or changing dashboard UI.
Use its shared page structure, semantic colors, number formatting,
accessibility rules, and review checklist. Extend shared UI components
before introducing page-specific variants. Record any deliberate deviation
and its reason in the change description.

The guide's visual direction is demonstrated in `static/prototype/`.
It is a standalone mock with illustrative data, not a production data source.
Do not connect its demo parameter actions to an engine or use its fixture
values as trading defaults. Production behavior and repository architecture
rules remain authoritative during migration.
